# 💰 Finance Bot — приватный финансовый трекер в Telegram

Локальный бот учёта расходов и кредитов: Telegram (aiogram 3) + локальные модели через Ollama: текстовая для разбора трат и **модель зрения (VLM) для чтения фото чеков**. Tesseract работает вторым, независимым читателем — проверяет арифметику чека. Всё работает на твоём ноутбуке, данные никуда не уходят.

## Возможности

- 🚀 **Приветственная настройка** — новый пользователь вместо пустого экрана проходит 5 шагов: знакомство, имя, ожидаемый доход и бюджет по доходу (70% от дохода, остальное — накопления). Пройти заново: ⚙️ Настройки → 🚀 Пройти настройку заново
- 📝 **Траты текстом** — напиши «Заправка 2000» или «ДНС 5000» из любого экрана: ИИ сам определит сумму, категорию, подкатегорию, доход или платёж по кредиту
- 🕘 **История и отмена** — последние записи доступны отдельной кнопкой; ошибочную последнюю операцию можно отменить, а платёж по кредиту автоматически вернётся в остаток
- 📷 **Фото чека** — локальная модель зрения читает чек целиком (таблица, блёклый и наклонный текст), Tesseract сверяет цифры и помогает добрать пропущенные позиции (см. «Как работает разбор чека»); позиции с краткими названиями сохраняются в базе
- 🔎 **Видно, кто читал чек** — в карточке написано, что чек разобрала модель зрения и сколько было проходов, или что читал Tesseract: доверие к названиям позиций разное, и это честно показано
- 📈 **Диаграммы** — отчёты приходят картинкой в тёмной теме: кольцо долей по категориям, полосы с суммами, полоса остатка бюджета и прогноз к концу месяца
- 🟢 **Безопасно тратить в день** — по плану дохода бот считает, сколько можно тратить в день до конца месяца
- 🛒 **Разбор корзины** — по каждому товару вердикт, причина и что делать; суммы и доли по группам, план на следующую закупку. Алкоголь и чипсы НИКОГДА не называются полезной покупкой
- 📈 **Контроль цен** — новый чек сравнивается с предыдущими чеками пользователя только по тому же товару, бренду и упаковке; разные продукты одной категории не смешиваются
- 🍺 **Алкоголь и снеки — это досуг** — если их заметная часть чека, бот сам ставит категорию «досуг» (или предлагает кнопкой «🎮 Это досуг, не еда»)
- 🧾 **Карточка перед записью** — видно сумму, магазин, категорию, позиции и остаток лимита; всё можно поправить
- 🎯 **Бюджет правится в самом боте** — лимиты по категориям и общий лимит живут в БД (⚙️ Настройки → 🎯 Бюджет)
- 🤖 **ИИ-бюджет по истории** — после месяца-двух работы бот сам предлагает лимиты на месяц по фактическим тратам
- 📊 **Отчёты** — месяц, неделя, 90 дней, совместный, «Совет ИИ», диаграмма
- 🖥 **Панель управления на Tkinter** (`panel.py`) — база, чеки с позициями, лимиты, долги, настройки каждого пользователя и выгрузка CSV. Выгрузка CSV переехала из бота сюда
- 💻 **Своя категория «техника»** — ДНС, М.Видео, Ситилинк, комплектующие, гаджеты
- 💳 **Долги** — остатки, прогресс выплат, платежи, прогноз погашения
- 🚨 **Алерты** — предупреждение при 90% и превышении лимита, ежедневная сводка вечером

## Установка (Windows 11)

### 1. Python 3.11/3.12
Скачай с [python.org](https://www.python.org/downloads/), при установке отметь **Add Python to PATH**.

### 2. Ollama и модель
Скачай с [ollama.com](https://ollama.com/download), установи, затем в консоли:
```bash
ollama pull qwen2.5:7b-instruct     # ~4.7 ГБ — основная модель, точный разбор трат
```
Если 7B тяжело для ноутбука — хватит и меньшей (`qwen2.5:3b-instruct`). Бот сам подхватит лучшую из установленных моделей: сначала `OLLAMA_MODEL` из `.env`, затем любую из внутреннего списка предпочтений. Активную модель видно в **⚙️ Настройки → 🩺 Статус сервисов** и в консоли при запуске.

Без установки Ollama можно работать через облако: `OLLAMA_HOST=https://ollama.com` + `OLLAMA_API_KEY` (ключ с [ollama.com/settings/keys](https://ollama.com/settings/keys)).

### 3. Модель зрения для чеков
```bash
ollama pull qwen3-vl:8b-instruct    # ~6 ГБ — лучшее качество чтения чеков
# или, если карта слабая / мало VRAM:
ollama pull qwen3-vl:4b-instruct    # ~3.3 ГБ, быстрее
```
Бот сам найдёт скачанную модель зрения из списка предпочтений и покажет её в **⚙️ Настройки → 🩺 Статус сервисов**. Чтение можно выключить (`VISION_ENABLED=0` в `.env`) — тогда чеки читает только Tesseract.

### 4. Tesseract OCR (проверка цифр)
Установщик: [UB-Mannheim/tesseract](https://github.com/UB-Mannheim/tesseract/wiki) (`tesseract-ocr-w64-setup-*.exe`, ~50 МБ). Путь `C:\Program Files\Tesseract-OCR` бот находит сам, иначе укажи `TESSERACT_CMD` в `.env`.

Нужен русский язык: положи `rus.traineddata` (и по желанию улучшенный `eng.traineddata`) из [tessdata_best](https://github.com/tesseract-ocr/tessdata_best) в `C:\Program Files\Tesseract-OCR\tessdata\`. Проверка: `tesseract --list-langs` должен показать `rus`.

### 5. Проект
```bash
cd finance_bot
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

### 5. .env
```
BOT_TOKEN=токен_от_@BotFather
USER_ID_1=твой_id_от_@userinfobot
USER_ID_2=id_второго_пользователя
```

### 6. Запуск
```bash
python bot.py
```

## Интерфейс

- Снизу — reply-кнопки: 💸 Добавить трату, 📷 Скан чека, 📊 Отчёт, 💳 Долги, 💰 Доход, ⚙️ Настройки, 🕘 История и ↩️ Отменить последнюю.
- `/start` — мини-сводка месяца (потрачено, лимит, топ-категория, долги) и кнопки быстрых действий, `/menu`, `/help`, `/report`.
- **Любое текстовое сообщение** (кроме команд и кнопок меню) бот пытается разобрать как трату — не нужно сначала нажимать кнопку. После записи бот возвращает меню с кнопками.
- Первый `/start` у нового пользователя открывает приветственную настройку; у того, у кого уже есть записи, она не показывается (можно запустить вручную из ⚙️ Настроек).
- **Бюджет:** ⚙️ Настройки → 🎯 Бюджет → нажми категорию → введи сумму числом или выбери быструю. Там же кнопка «🤖 Предложить бюджет» — она считает лимиты по истории (доступна, когда накоплено ≥30 дней трат) и предлагает применить одной кнопкой.
- Плашка веб-приложения от старых ботов убирается автоматически при запуске (`setChatMenuButton` + список команд). Если в клиенте осталась старая панель — переоткрой чат; совсем убрать настройку можно в @BotFather → Bot Settings → Menu Button.

## Как работает разбор чека

Чек читается **двумя независимыми способами**, потом результаты сводятся по арифметике.

**1. Модель зрения (`ai/vision.py`, qwen3-vl).** Локальная VLM получает фото чека целиком и возвращает структуру: магазин, дата, итог, категория и все позиции (название, количество, цена, сумма). Она видит таблицу как человек: понимает, где название, где цена, а где итог, читает блёклый и наклонный текст и разворачивает сокращения чека. Числа модель обязана переписывать ровно как на чеке; ответ — строгий JSON (`format=json`), температура 0.

**2. Tesseract (`ai/ocr.py`).** Второй, независимый читатель — без нейросети, зато с проверяемой арифметикой:

1. обрезка фона и цветных пометок, upscale и контраст (несколько вариантов предобработки, включая шумоподавление OpenCV);
2. OCR с координатами каждого слова (`image_to_data`);
3. сборка строк по вертикали;
4. **поиск колонок**: числа в чеке выровнены по правому краю, поэтому их правые края собираются в плотные кластеры. Колонка «итого» дополнительно привязывается к сумме из строки «ИТОГ», левее ищутся «цена», «кол-во», «скидка»;
5. сборка позиций: одна сумма в колонке «итого» — одна позиция, название копится из соседних строк;
6. **склейка разорванных чисел**: «1234» + «‚56» → 1 234,56, «1» + «099,99» → 1 099,99, «5 В 099,00» → 5099;
7. **проверка арифметики**: если «цена × количество» не сходится с суммой позиции, ячейка перечитывается крупным планом с whitelist цифр;
8. **выбор лучшего разбора по итогу чека**. Итог печатает касса, и он не зависит от того, как OCR разобрал таблицу, поэтому варианты предобработки сравниваются по одному признаку: насколько позиции объясняют итог. Разбор, который оставляет непонятный остаток, потерял или выдумал строку — его не берут, даже если он «красивее»;
9. **согласие проходов**: одна и та же строка читается несколькими вариантами обработки, и разные варианты ошибаются по-разному. Где проходы согласны по сумме — цене можно верить; где расходятся — цифра помечается как спорная;
10. **добор по остатку**: если у строки прочитано название, но потеряна вся правая ячейка, её цену даёт остаток чека («итог минус остальные позиции»), а крошечный остаток (до 0,5%) закрывает единственная неподтверждённая позиция — так «2.42» превращается обратно в «2.72»;
11. **шапка и реквизиты не попадают в товары**: строки вида «ИТОГ», «подытог» (даже прочитанные как «noanuTor»), «ценник», «кассир», ФИО и адреса отсеиваются до сборки позиций, а название обрывается там, где начинается первая числовая колонка.

## Как строится разбор корзины

После записи продуктового чека бот присылает разбор — по каждому товару отдельная строка с причиной и действием:

```
🛒 Разбор корзины — Пятёрочка
Чек 844,30 ₽ · позиций: 6

❌ Лучше сократить — 358,90 ₽ · 43% чека
   • Чипсы Lays 120г — 149,90 ₽
     ↳ снек, много калорий → взять орехи или фрукты
   • Шоколад Милка — 120 ₽
     ↳ сладкое, много сахара → заменить фруктами

💰 Необязательные траты: ~358,90 ₽ · 43% чека
📉 Реально сократить в следующий раз: ~259 ₽

📌 Что делать в следующий раз:
   1. Уменьшить покупку чипсов до 50 г
   2. Пить пиво только по праздникам
```

Что делает разбор подробным и честным:

1. **Причина + действие по каждому товару** (`reason` и `note` в `ai/llm.py`). В промпте прямо запрещены пустые советы («заменить», «полезнее», «досуг») и один и тот же совет двум разным товарам.
2. **Вычистка повторов** (`apply_review_rules` → `_dedupe_advice`): если модель приписала одинаковый текст нескольким товарам («хлеб заменить» и маслу, и сметане) — это значит, что она не смотрела на товар, и такой совет убирается у всех.
3. **Страховки по типу товара** (`ai/receipts.py`). Алкоголь и снеки никогда не «полезно» (заменяется готовым советом по типу: пиво, вино, крепкое, энергетик, снеки, сладкое, газировка — у каждого свой); настоящая еда не бывает «лишней» (макароны, крупы, консервы — типовая ошибка модели «ненужные перья»); упаковка и мелочи (пакет, заколки, игрушки) — только «лишнее» с понятной причиной; гигиена и бытовая химия — «нейтрально», не «полезно».
4. **Суммы по группам и доли чека** считает сам бот по вердиктам — видно, из чего сложился итог. Оценка модели («реально сократить») показывается отдельно: необязательное ≠ то, что человек урежет.
5. **Сравнение цен с историей** работает консервативно: ищется тот же товар, а не просто «любая сметана» или «любая колбаса». Сигнал появляется только при заметном росте цены (не менее 10 ₽ и 12%).
5. **План на следующую закупку** — 2–3 конкретных шага с суммами.

**3. Подготовка фото (то же, что делает OCR, но в цвете).** Модель зрения не получает сырое фото: `ai/ocr.py::vision_variants` вырезает чек (убирая фон, руки и цветные пометки), выпрямляет наклон по чернильным пикселям, поднимает резкость и контраст и отдаёт три варианта — `crop` (обрезка), `clean` (снятые тени + резкость) и `raw`. Основное чтение идёт по `crop`, для второго прохода готов запас.

**4. Добор потерянных позиций по арифметике (`_gap_fill`).** Самая частая ошибка чтения — не «съехавшая» цена, а пропущенная строка: модель уверенно читает итог и все позиции, кроме одной, и раньше эта разница просто терялась. Теперь недостача (итог минус сумма позиций) ищется среди позиций Tesseract, которых нет в чтении модели, и подходящая по сумме добавляется. Такая позиция помечается `recovered`, `verified=False` — карточка честно пишет, что часть цен прочитана неуверенно.

**5. Второй проход модели зрения (`VISION_SECOND_PASS`).** Если после добора позиции всё ещё расходятся с итогом больше чем на 1% (но не меньше 5 ₽), чек перечитывается вариантом `clean` с промптом, нацеленным на таблицу позиций: «иди строку за строкой, сумма позиций должна совпасть с итогом». Из двух чтений берётся то, что ближе к итогу чека. На реальном чеке Пятёрочки хватило добора: второй проход не понадобился.

**Сведение чтений (`_merge_readings`).** Кто прочитал точнее, решает арифметика, а не уверенность модели: у верного чтения сумма позиций равна итогу чека. Сходятся оба — берём то, где больше позиций. Ни у кого — то, что ближе к итогу. Дальше совпавшие позиции двух чтений помечаются подтверждёнными, расхождения решаются в пользу числа, при котором сумма позиций ближе к итогу, а сокращения разворачивает текстовая модель (числа она **не меняет**).

Если модель зрения недоступна или не влезает в VRAM, чеки читает Tesseract — бот не падает. На картах на 12 ГБ текстовая модель на время чтения выгружается и поднимается обратно в фоне (`VISION_UNLOAD_CHAT`). Модель подбирается **строго по тегу**: `qwen3-vl:8b-instruct` больше не подменяется на `qwen3-vl:4b`, а `qwen2.5:7b-instruct` — на `qwen2.5:7b` (раньше это молча ухудшало качество).

На реальных чеках бот сходится копейка в копейку. Чек электроники уходит в категорию «техника» с позициями вроде «БП Deepcool PF750 750W» и «Корпус ZALMAN N4», а сумма позиций совпадает с итогом чека. Продуктовый чек с пивом и снеками получает категорию «досуг» (не «еду»), позиции разбираются по одной, а добор `_gap_fill` возвращает строку, которую пропустило чтение.

Свои чеки для этих прогонов не попадают в репозиторий: тесты берут их из локального `receipt_samples.json` (см. «Проверка»).

## Интерфейс отчётов картинкой

`services/charts.py` рисует отчёт через matplotlib (тёмная тема, без эмодзи — только цифры и цвета, которые совпадают у кольца и полос). Если matplotlib не установлен, отчёты просто остаются текстовыми: `charts.*` возвращают `None`, а бот отправляет текст.

- `/report` и кнопка «📅 Месяц» — картинка («кольцо долей + полосы по категориям + полоса остатка бюджета + прогноз») и следом текст с лимитами по категориям;
- «📆 Неделя» и «🗓 90 дней» — картинка с тратами по дням (заливкой) плюс текстовый отчёт;
- «📈 Диаграмма» — только картинка, для быстрого взгляда.

## Панель управления (Tkinter)

```bash
start_panel.bat                 # или: venv\Scripts\python.exe panel.py
```

Панель работает с той же базой `data/finance.db`, что и бот, поэтому её можно держать
открытой рядом: блокировки БД пережидаются (`PRAGMA busy_timeout`), Telegram продолжает
принимать траты.

| Вкладка | Что внутри |
|---|---|
| **Обзор** | KPI за период (потрачено, доход, баланс, долги), полосы трат по категориям на Canvas, фильтр по пользователю и периоду |
| **Транзакции** | Таблица с фильтрами (пользователь, период, тип, поиск), добавление, правка и удаление записей, позиции выбранного чека снизу |
| **Чеки** | Все чеки с фото: магазин, итог, категория, число позиций; ниже — сами позиции с ценой и суммой |
| **Бюджет** | Лимиты по категориям и общий, напротив каждого — трата за месяц и остаток («перерасход …»); кнопки «Сохранить», «Предложить по доходу» (70% плана дохода), «Сбросить к стартовым», «Показать графики бота» — открывает ту же картинку, что бот шлёт в Telegram; ниже — долги с правкой остатка |
| **Пользователи** | По каждому: имя, роль, план дохода, пройдена ли настройка, число записей, траты и доход за месяц, последняя активность. Можно переименовать, задать доход, отправить на приветственную настройку заново и открыть его траты |
| **Экспорт CSV** | Выгрузка за период по пользователю или по всем: формат собирает тот же `services/export.py`, что раньше отправлял файл в Telegram, — один владелец формата |

Лимиты и настройки панель пишет теми же ключами, что и бот (`limit:{категория}`, `limit:total`,
`profile:{id}:{имя, доход, onboarded}`), — поэтому изменения сразу видны в Telegram, а «План дохода»
включает строку «🟢 Безопасно тратить» на главном экране бота.

## Проверка

```bash
venv\Scripts\python.exe smoke_test.py       # модули, БД, аналитика, добор позиций, диаграммы, профиль
venv\Scripts\python.exe handlers_test.py    # реальные апдейты через диспетчер (настройка, меню, кнопки, чек)
venv\Scripts\python.exe receipt_test.py     # разбор чека по фото + продуктовый чек и разбор корзины
```
`handlers_test.py` подменяет сетевую сессию Telegram и проверяет, что у каждой кнопки есть обработчик и что разметка сообщений не ломается. `receipt_test.py` проверяет чек электроники, продуктовый чек с таблицей, узкий чек «кол-во × цена = итого» и разбор корзины.

### Свои чеки в тестах

Фото чеков и реальные суммы — личные данные, поэтому в репозитории их нет: `receipt_samples.json` в `.gitignore`. Чтобы прогонять тесты на своих чеках, скопируй шаблон и заполни его:

```bash
copy receipt_samples.example.json receipt_samples.json
```

```json
{
  "grocery": {
    "photo": "data/receipts/мой-чек.png",
    "total": 1234.56,
    "is_grocery": true,
    "min_items": 10,
    "sum_tolerance": 120,
    "name_tokens": ["пиво"]
  }
}
```

Ключи образцов: `dns` (чек электроники), `grocery` (продуктовый с колонками), `narrow` (узкая таблица «кол-во × цена = итого»). Есть образец — проверка сверяет с ним; нет — печатает пропуск. Путь к фото можно передать и аргументом: `receipt_test.py путь\к\чеку.png` (тогда проверки с эталоном пропускаются).

В боте: **⚙️ Настройки → 🩺 Статус сервисов** — доступность Ollama, модель разбора трат, модель зрения для чеков и Tesseract.

## Ограничения
- Первое чтение чека моделью зрения грузит модель в память (~10–40 с), дальше она отвечает за несколько секунд и держится в памяти (`VISION_KEEP_ALIVE`). Чтение одного чека на видеокарте уровня RTX 3060 занимает ~30 с; второй проход включается только при расхождении с итогом.
- Позиции, добавленные добором (`recovered`), могут быть не той строкой чека: арифметика сходится, но название пришло от Tesseract. Карточка помечает такие позиции ⚠️.
- Фото всё ещё должно быть резким: на совсем мутном снимке ни модель, ни OCR не спасут. Если итог не найден, напиши сумму текстом («ДНС 5000»).
- Название магазина бот не выдумывает: если его нет в тексте чека, покажет «Чек» или имя, которое разобрал. Категорию и сумму всегда можно поправить до записи.
- Если цены в позициях не сходятся с итогом, карточка чека предупредит об этом: одно из чтений могло ошибиться, итог важнее.
- Без Ollama бот не падает: траты разбираются правилами по ключевым словам, чеки — только Tesseract-ом (если он установлен).
- ИИ-предложение бюджета появляется, когда есть ≥30 дней истории трат (настраивается `BUDGET_MIN_DAYS`).
- Бот отвечает только тем, чьи Telegram ID указаны в `.env` (whitelist на всех роутерах).

## Что с данными и демо-значениями

- В репозиторий не попадают: `.env` (токен и Telegram ID), `data/` (база, фото чеков), `receipt_samples.json` (образцы чеков владельца), логи и виртуальное окружение — всё это в `.gitignore`.
- Демо-значения, которые нужно заменить своими: стартовые лимиты в `config.py` (`MONTHLY_LIMITS`, `TOTAL_MONTHLY_LIMIT`) и стартовые долги в `database/models.py` (`INITIAL_DEBTS`, по 1 000 ₽, чтобы бот завёлся на чистой базе). Свои лимиты и долги правятся в боте или в панели управления, а не в коде.
