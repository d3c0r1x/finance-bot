# Finance Bot: дорожная карта Android + Telegram до SaaS

Версия 1.0, 2026-10-12. Этот документ задаёт актуальное направление продукта и дополняет прежний `PLAN.md`.

## 1. Цель

Довести Finance Bot до бесплатного закрытого MVP для владельца и знакомых, затем подготовить его к SaaS. В MVP вся финансовая логика работает через backend; пользовательские клиенты — Android и Telegram. Отдельного сайта, финансового Web UI или Web-панели не будет.

MVP должен покрывать все согласованные финансовые сценарии в Android и Telegram. Допускается временно шероховатый интерфейс и временная недоступность AI при лимитах провайдера. Нельзя показывать фиктивный успех, терять финансовые данные или давать другим пользователям доступ к чужим данным.

## 2. Решения пользователя

- Android-приложение распространяется вручную в виде APK. Пользователь устанавливает APK и сам регистрируется. Пригласительные коды не нужны.
- Telegram доступен только ID из серверной конфигурации allowlist.
- У одного человека общий профиль и общие финансовые данные в Android и Telegram. Привязку Telegram ID оператор задаёт на сервере; бот не просит пользователя вводить invite/link-код.
- Production database стартует пустой. Синтетические записи разрешены только в тестах и локальной демонстрации; в production seed финансовых данных нет.
- Приложение и backend ориентированы на РФ. Первичная база финансовых данных и файлы должны размещаться в российском дата-центре.
- Сервер считает суммы, бюджеты, отчёты, прогнозы, проверки и агрегаты. Клиенты отображают серверные результаты и отправляют пользовательские действия.
- Gemini используется для разбора чеков, рекомендаций и других AI-задач. Задачи распределяются по поддерживаемым моделям с учётом возможностей, сложности и доступных лимитов.
- При лимите отдельной модели разрешён переход на другую подходящую модель. Если нет доступной модели, приложение показывает «Временно недоступно»; ручной учёт продолжает работать.
- Пользователь принимает актуальную версию политики и условий обработки при регистрации. В документах отдельно описывается передача минимально необходимых данных Gemini.
- Monetization, платёжный UI, публичный магазин приложений и нагрузочная инфраструктура не входят в бесплатный MVP.

## 4. Продуктовая архитектура MVP

```text
Android APK ──HTTPS + OIDC──┐
                            ├── Java Core API ── PostgreSQL в РФ
Telegram ── Python Gateway ┘         │
                                     ├── Python Intelligence Gateway ── Gemini API
                                     └── private object storage в РФ
```

- Java Core остаётся владельцем пользователей, tenant membership, финансовых операций, прав, аудита и расчётов.
- PostgreSQL — source of truth. Каждый запрос имеет проверяемый account/tenant context. Существующий row-level security сохраняется.
- Android Kotlin/Compose и Telegram используют одни API-контракты и один профиль пользователя.
- Telegram Gateway отвечает только за Telegram transport, сценарии, форматирование и вызов Core. Финансовые правила и SQL не переносятся в Python bot.
- Серверная аналитика остаётся серверной. Текущий Go worker сохраняется там, где он уже нужен расчётам. Новые Kafka, ClickHouse, Redis или отдельные микросервисы добавляются только после доказанной потребности конкретного сценария.
- Gemini credentials хранятся только на backend. Текст и изображения проходят минимизацию; модели возвращают предложения в валидируемой схеме. Денежные изменения применяются только Core после подтверждения пользователя.
- Model routing использует только модели с нужными capabilities. Независимые задачи можно выполнять параллельно в пределах лимитов. Повтор одной задачи на всех моделях без необходимости запрещён.
- Ручная запись трат, доходов, бюджетов и долгов не зависит от доступности Gemini.

## 5. Регистрация и общий профиль без кодов

1. Android-пользователь создаёт аккаунт через Keycloak self-registration и подтверждает email.
2. Приложение создаёт личное финансовое пространство в Core. По умолчанию доступ один у владельца.
3. Оператор добавляет Telegram ID в закрытый серверный allowlist и связывает его с тем же каноническим аккаунтом. Бот не просит link-код.
4. При каждом Telegram update Gateway проверяет allowlist, а Core заново проверяет пользователя, membership, tenant и роль. ID вне списка получает отказ без обращения к финансовым данным.
5. Повторная привязка, удаление из allowlist, конфликт ID и отсутствующий аккаунт имеют явное безопасное поведение. Пользовательские invite/link-коды не используются.

Текущий Core пока не поддерживает Telegram-only principal: actor context и часть сервисов требуют Keycloak subject. Поэтому ветка для участника без Android остаётся незавершённым MVP требованием. Реализовать её через отдельную Telegram identity и безопасное прикрепление подтверждённого OIDC subject к тому же `users.id`; не подделывать Keycloak identity и не сливать аккаунты автоматически.

Для iPhone-only участника оператор может создать Telegram-профиль в Core и внести его ID в тот же allowlist. Если такой пользователь позже регистрируется в Android, оператор связывает OIDC identity с тем же каноническим аккаунтом до открытия доступа. Автоматическое слияние финансовых профилей не выполняется.

## 6. Gemini, лимиты и доступность

Для первой конфигурации сохраняется список моделей и квот из предоставленного пользователем снимка Gemini dashboard. Этот снимок — исходная настройка, а не гарантия текущих квот: фактические model IDs, capabilities и пределы проверяются через используемый проект перед запуском.

| Модель из снимка | RPM | TPM | RPD | Начальная задача |
|---|---:|---:|---:|---|
| Gemini 3.8 Flash | 5 | 250 000 | 20 | Сложный анализ и рекомендации |
| Gemini 3.1 Flash Lite | 15 | 250 000 | 500 | Лёгкие текстовые задачи и drafts |
| Gemini 3.5 Flash Lite | 15 | 250 000 | 500 | Резервная лёгкая модель после проверки capability |
| Gemma 4 26B | 30 | 16 000 | 14 400 | Дополнительная модель только для прошедших evaluation задач |

В снимке также указано, что prepay credits исчерпаны. Пока баланс или активная квота не восстановлены, все Gemini-вызовы могут быть недоступны одновременно. Система не считает указанное значение RPD гарантией бесплатных рабочих вызовов.

Планируемое поведение:

- лёгкие текстовые задачи и классификация направляются в доступную Flash Lite модель;
- разбор чека использует доступную модель с image/structured output; независимые чтения запускаются параллельно только при свободном лимите;
- сложные рекомендации направляются в более способную Flash-модель;
- Gemma включается только для задач, которые прошли synthetic evaluation на точность и корректность JSON;
- ответ 429 отмечает конкретную модель как временно ограниченную и запускает одну подходящую резервную модель;
- 5xx/timeout допускают ограниченный повтор или fallback по deadline;
- исчерпанный общий billing credit, отсутствие активной квоты или отказ всех моделей возвращают безопасное состояние `temporarily_unavailable` и локализованную плашку;
- UI не показывает внутренние коды, ключ, сырой ответ Gemini или текст исключения;
- при любой ошибке Gemini OCR/Tesseract/manual review остаются доступны, где это возможно.

#### Ограничения, которые влияют на production gate

Официальный список Gemini Developer API не включает РФ; условия Gemini API разрешают предоставлять API-клиент только пользователям доступных регионов. Google предлагает рассмотреть Gemini Enterprise Agent Platform для регионов вне списка, но её endpoint не гарантирует data residency. Поэтому нельзя обещать live Gemini для российских пользователей без проверки допустимого официального маршрута и обработки трансграничной передачи. Код можно подготовить и проверить на mock transport; production-вызовы не маскируются VPN, proxy или подменой региона.

Google также запрещает отправлять sensitive, confidential или personal information через unpaid Gemini services. Для реальных чеков и персональных финансовых рекомендаций AI включается только при условиях обработки, подходящих для таких данных, и после явного раскрытия пользователю передаваемых полей. Истощённый баланс ведёт к плашке недоступности, а не к скрытой отправке в free tier.

## 7. Приватность и РФ

- Primary database, резервные копии и receipt objects размещаются в РФ.
- К Gemini отправляются только поля, необходимые для конкретной задачи. Идентификаторы пользователя, tenant, email и история целиком не отправляются.
- Фото чеков имеют отдельную обработку: удаление метаданных, ограничение размера, безопасный upload, короткий retention AI-копии и отсутствие текста чека в telemetry.
- Согласие хранит версию документа, дату, пользователя и язык. Отказ оставляет только функции, не требующие такой обработки.
- Политика, пользовательское соглашение, отдельное описание AI и согласие на обработку данных получают настоящие реквизиты оператора до выдачи друзьям.
- Это продуктовый проект юридических текстов, не юридическое заключение. Перед production нужен юрист по 152-ФЗ и трансграничной передаче.

## 8. Этапы до бесплатного MVP

### M0. Зафиксировать актуальное направление

- Привести `PLAN.md`, `docs/specs/CONTINUATION.md`, личный MVP plan и `.agent/PROGRESS.md` к решениям этого документа.
- Удалить Web UI из acceptance criteria и parity как пользовательский клиент. Оставить backend API и OpenAPI contracts.
- Сверить весь F01–F58 registry по Android и Telegram. Не считать запись `partial` завершённой.

**Gate:** один согласованный roadmap, ясный набор Android/Telegram функций, текущие dirty-файлы владельца сохранены.

### M1. Доступ, аккаунт и пустой старт

- Завершить Keycloak self-registration, email verification/reset, Android entry screen и защищённый вход.
- Заменить user-entered Telegram link code на конфигурационный ID allowlist с привязкой к каноническому Core account.
- Проверить tenant/member isolation и deny для ID вне списка.
- Запускать production schema с пустой базой. Synthetic seed доступен только в dev/test profile.

**Gate:** чистая установка APK, регистрация без invite-кода, вход, один профиль, Telegram whitelist и общие данные в обоих клиентах; чужой профиль недоступен.

### M2. Надёжный API и хранение данных

- Развернуть минимальный runtime: Core, PostgreSQL, Keycloak, Telegram Gateway, Intelligence Gateway, приватное файловое хранилище и HTTPS.
- Подтвердить размещение БД, backups и файлов в РФ, автозапуск, health check, restart, logs без личных данных.
- Убрать `start-dev`, локальные credentials и debug HTTP из release/runtime конфигурации.

**Gate:** перезапуск не теряет записи; backup restore проверен; public API доступен только по HTTPS; анонимный финансовый API закрыт.

### M3. Полный рабочий финансовый набор

- Закрыть все Android `partial/missing` mappings в registry по F01–F58. Telegram `N/A` разрешён только там, где у функции нет пользовательского сценария в Telegram: `legacy_ui_layout`, `operator_only`, `developer_only` или `protocol_specific`. Для каждого такого исключения указать категорию, причину и источник утверждения; финансовый пользовательский сценарий нельзя скрывать под N/A, если он уже описан отдельным F-ID.
- Подтвердить, что Telegram покрывает те же финансовые сценарии и общую историю.
- Все расчёты, правила бюджетов, долги, отчёты, импорт, дедупликация и экспорт подтверждаются Core.
- Синтетические fixtures проходят один и тот же backend contract для Android и Telegram.

**Gate:** parity matrix не содержит необъяснённых пропусков; полные пользовательские сценарии проходят на обоих клиентах; деньги совпадают и не рассчитываются отдельно в UI.

### M4. Gemini features и graceful degradation

- Реализовать официальный Gemini API adapter и маршрутизацию моделей по capabilities и task complexity.
- Добавить timeout, rate limiting, quota-aware fallback, circuit breaker и usage/provenance log без содержимого чеков.
- Добавить Gemini consent, минимизацию и доступные AI features: receipt extraction, transaction draft, recommendations, budget proposal и merchant suggestion.
- Если официальный API/квота недоступны, показывать «Временно недоступно»; ручной ввод работает.

**Gate:** synthetic evaluation, mock provider tests, per-model 429 fallback, общий out-of-credit и полный provider outage проверены; production enable только после проверки региона, тарифа и data policy.

### M5. Тестирование с друзьями

- APK устанавливается вручную, в нём нет test credentials и локальных адресов.
- Участник сам регистрируется; Telegram ID добавляет оператор.
- Новая БД пуста, все профили изолированы, события и операции сохраняются после перезапуска.
- Privacy policy, условия, AI disclosure, data export/delete и контакты оператора показаны до соответствующих действий.
- Ошибки API, сети, Telegram и Gemini имеют ясные состояния; никакая ошибка не создаёт фиктивную финансовую операцию.

**Gate:** владелец и минимум два synthetic friend-account проходят UAT в Android и Telegram; найденные дефекты записаны и исправлены; live production AI возможен только при пройденном M4 gate.

## 9. Этапы от MVP до SaaS

### S1. Закрытая free beta

Стабильная ручная раздача APK, Telegram allowlist, поддержка пользователя, резервное копирование, мониторинг ошибок и ручное управление доступом. Без публичной регистрации в магазине и без платежей.

### S2. Готовность продукта к оплате

Публичные правила доступа, планы и лимиты, точное учётное использование AI/storage, self-service export/delete, поддержка, операционные панели в виде CLI/config/API, а не Web UI. Платёжный провайдер и налоги выбираются после подтверждения оператора и рынка.

### S3. Платный pilot

Sandbox и live платежи, подписи webhook, возвраты, отмена, просрочка, reconciliation, тарифные изменения без потери истории. Ограниченная группа пользователей и наблюдаемая себестоимость.

### S4. SaaS release

Проверенная безопасность tenant isolation, восстановление backup, нагрузка по фактическим метрикам, релиз/rollback APK и backend, политика данных и поддержки, legal review, incident response и измеренная стоимость AI.

Kafka/ClickHouse, горизонтальное масштабирование и новые сервисы добавляются на S2–S4 только при измеренной необходимости. Не блокировать MVP инфраструктурой для неподтверждённой нагрузки.

## 10. Definition of Done MVP

- В product repo нет user-facing Web UI; backend API, OpenAPI, health endpoints остаются.
- Android APK работает на согласованном минимальном Android API, проходит ручную установку и использует настоящий HTTPS backend.
- Android self-registration и Telegram allowlist без invite/link-кодов доступны по условиям выше.
- Один человек видит одни финансовые данные в обоих каналах; разные люди изолированы.
- Все согласованные F01–F58 сценарии имеют Android/Telegram acceptance или чёткое обоснование N/A.
- Финансовые расчёты и business mutations выполняет backend.
- Production DB создаётся пустой; синтетические данные не попадают в production.
- Receipt files и database backups хранятся приватно в РФ; deletion/export проверены.
- AI работает через Gemini только по включённому официальному маршруту. Quota exhaustion показывает «Временно недоступно» и не блокирует ручные сценарии.
- Актуальные privacy/terms/AI documents приняты пользователем; реквизиты оператора заполнены.
- E2E проверяет два аккаунта, два клиента, отказ чужого доступа и сохранность после рестарта.

## 11. Решения, которые остаются операционными gates

Они не меняют выбранный продукт, но нужны до конкретного этапа:

1. Для MVP выбран Gemini Developer API. Включение реальных запросов остаётся закрытым до подтверждения доступности аккаунта/региона, тарифа и условий обработки данных. Региональные ограничения не обходить.
2. Российский cloud/host, домен, TLS и почтовый sender для подтверждения email.
3. Юридическое лицо/оператор (физлицо, ИП или ООО), контакты и адрес для финального текста согласий.
4. API keys для Gemini и лимиты расходов. Секреты передаются только через локальный secret store, не в Git и не в чат.
