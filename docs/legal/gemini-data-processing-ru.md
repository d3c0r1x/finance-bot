# Уведомление об обработке данных при использовании Gemini

> **Черновик описывает планируемую функцию, а не подтверждает, что Gemini включён или доступен пользователям в России.** По состоянию на 12 октября 2026 года публичный список регионов Gemini API не содержит Россию, а условия Google разрешают доступ к API и предоставление API-клиента пользователям только в доступных регионах. Поэтому передача реальных данных пользователей из России в Gemini сейчас должна оставаться отключённой. Не обходить региональные ограничения через прокси, чужой аккаунт или фиктивное местоположение. Перед запуском нужен официальный подтверждённый маршрут, проверка условий и заключение российского юриста.

**Версия:** `{{AI_NOTICE_VERSION}}`
**Дата вступления в силу:** `{{EFFECTIVE_DATE}}`
**Оператор:** `{{OPERATOR_LEGAL_NAME_OR_FULL_NAME}}`
**Контакт:** `{{SUPPORT_EMAIL_OR_OTHER_CONTACT}}`

## 1. Когда может использоваться Gemini

Продукт планирует использовать Gemini Developer API для ИИ-задач, которые запускает сам пользователь, например:

- распознать изображение чека и подготовить черновик операции;
- предложить категорию или торговую точку;
- подготовить рекомендацию или план по ограниченному набору агрегированных показателей.

Для работы обычных ручных функций финансового учёта Gemini не нужен. Если пользователь отказывается от ИИ или провайдер временно не работает, ИИ-функция отключается и показывается понятный статус. В рамках Gemini API условия Google требуют, чтобы пользователи API были не младше 18 лет и клиент не был предназначен для несовершеннолетних; возрастное ограничение и проверка должны быть определены до запуска этой функции.

**Фактический статус сейчас:** `{{AI_PROVIDER_STATUS_AND_DATE}}`. До подтверждения маршрута, договора и законности реальных запросов выставить статус «выключено для данных пользователей». Использовать только синтетические данные в изолированной тестовой среде.

## 2. Какие данные могут уходить в запросе

Перед конкретным запросом сервер должен сформировать только минимально нужные данные:

| Задача | Минимальный возможный состав запроса |
|---|---|
| Разбор чека | Изображение или выбранная область чека и краткая инструкция распознать товар, дату, сумму и валюту. |
| Черновик операции | Текст, введённый пользователем, и только относящиеся к операции сведения; не вся история аккаунта. |
| Категория/магазин | Название продавца или описание выбранной операции; не идентификаторы профиля. |
| Рекомендация | Только нужные агрегированные суммы/периоды и выбранная цель. Имена, email, Telegram ID, банковские логины и полная история не нужны и не должны включаться в запрос. |

Это требования к проектируемому поведению, а не проверенное описание текущих payload. До production оператор должен провести аудит фактических запросов и проверить, что лишние поля не отправляются. Если пользовательский материал содержит чужие персональные данные, пользователь должен удалить или замазать их до загрузки.

Запрещено направлять в модель пароли, коды подтверждения, API-ключи, полные данные банковских карт, CVV/CVC, банковские учётные данные, полную выгрузку истории «на всякий случай» и данные другого человека без надлежащего основания.

## 3. Кто получает данные и где они могут обрабатываться

Планируемый получатель — Google через Gemini Developer API. Точное юридическое лицо, роль получателя, страна обработки, применимые условия обработки и задействованные подрядчики зависят от конкретного Cloud-проекта и используемого продукта и должны быть заполнены до передачи реальных данных:

- Юридическое лицо Google / роль: `{{GOOGLE_ENTITY_AND_ROLE}}`.
- Применимый продукт и проект: `{{GEMINI_PRODUCT_AND_PROJECT}}`.
- Оплачиваемый режим и договор обработки: `{{PAID_BILLING_AND_DPA_STATUS}}`.
- Подтверждённые страны обработки: `{{GOOGLE_PROCESSING_LOCATIONS}}`.
- Уведомления/основания для трансграничной передачи, если применимы: `{{CROSS_BORDER_REVIEW_AND_FILINGS}}`.

Российская база, файлы и резервные копии не отменяют необходимости отдельно оценить передачу запроса иностранному лицу. Не включать маршрут до определения фактической цепочки получателей и проверки требований российского законодательства.

## 4. Бесплатный и оплачиваемый Gemini API

Условия Google различают неоплачиваемые и оплачиваемые услуги. Для неоплачиваемого Gemini API Google указывает, что может использовать отправленные запросы и ответы для предоставления, улучшения и разработки продуктов и моделей; сотрудники-рецензенты могут просматривать и аннотировать эти данные. Google прямо указывает: не отправляйте в неоплачиваемые услуги персональные, конфиденциальные или чувствительные сведения. Поэтому **реальные финансовые записи, чеки и персональные данные нельзя отправлять через неоплачиваемую квоту**.

Для оплачиваемого Gemini API Google указывает, что не использует запросы и ответы для улучшения продуктов, но может ограниченное время журналировать их для контроля нарушений правил и безопасности; такие данные могут временно храниться или кэшироваться в любой стране, где есть инфраструктура Google или его агентов. Точный применимый режим, условия и сроки нужно перепроверить для выбранного проекта перед запуском. Оплата сама по себе не подтверждает доступность API в России и не решает вопросы законности трансграничной передачи.

По состоянию на дату черновика опубликованный список доступных регионов Gemini API не содержит Россию. Условия API также ограничивают использование сервиса и предоставление клиентского приложения пользователям доступными регионами. Это означает, что в документации нельзя обещать, что Gemini сейчас легально или технически включён для российских пользователей. Оператор должен получить подтверждение Google о подходящем маршруте и провести юридическую проверку, прежде чем отправлять реальные данные.

Если провайдер, квота, регион, лимит или баланс недоступны, сервис возвращает сообщение **«Временно недоступно»**. Повторная отправка запроса на другую модель возможна только в допустимом и настроенном маршруте. Отказ провайдера не должен создавать или подтверждать финансовую операцию.

## 5. Результат ИИ и решение пользователя

Ответ Gemini может быть неточным, неполным или вымышленным. Он показывается как предложение. Пользователь должен проверить результат и сам подтвердить или исправить черновик. Gemini не принимает за пользователя финансовых решений, не проводит платежи и не меняет записи без его подтверждения.

ИИ-ответ не является финансовой, инвестиционной, налоговой, юридической, медицинской или иной профессиональной консультацией. Не полагайтесь на него как на единственный источник решения.

## 6. Согласие, отказ и удаление

ИИ-функция должна запускаться по отдельному действию пользователя и только после отдельного, понятного согласия на передачу перечисленных данных выбранному провайдеру. Согласие на ИИ не должно быть объединено с пользовательским соглашением. До внедрения учёта версий и отзыва согласия этот черновик не является доказательством принятия согласия.

Пользователь может отказаться от ИИ или отозвать согласие через `{{AI_CONSENT_WITHDRAWAL_FLOW}}` либо написать на `{{SUPPORT_EMAIL_OR_OTHER_CONTACT}}`. После отказа новые запросы не отправляются; ручное ведение учёта остаётся доступным. Удаление данных из систем Google возможно только в объёме и порядке, которые предоставляет применимый сервис и договор; оператор не обещает удаление уже обработанных запросов, пока не проверил соответствующую процедуру и срок.

Локально в журнале ИИ-провайдера не должны сохраняться текст, изображение или финансовая история пользователя. Допустимые технические сведения, срок хранения результата и процедура удаления: `{{LOCAL_AI_LOG_FIELDS_RETENTION_AND_DELETE}}`. Настройки логирования Gemini, использование `GenerateContent` или другого API, хранение файлов и любые функции grounding должны быть проверены до запуска. Grounding Search/Maps не включать без отдельной оценки: для него Google указывает дополнительные правила и хранение контекста и результатов до 30 дней.

## 7. Что нужно подтвердить до реальных запросов

- Текущая доступность для российского проекта и конечных пользователей письменно или по официальной документации Google.
- Применимость требования Google использовать API для профессиональных или деловых целей, а не для потребительского использования (`professional or business purposes, not for consumer use`) к закрытому приложению для личных финансов и его beta для друзей. До подтверждения от Google/юриста реальные запросы не включать.
- Совместимость выбранного использования с действующими условиями и коммерческим/оплачиваемым статусом API.
- Точное юридическое лицо Google, страны обработки, применимый договор обработки данных и субподрядчики.
- Правовое основание, отдельное согласие и требуемые уведомления/действия для трансграничной передачи.
- Минимизацию payload, отключение необязательного хранения и журналов, сроки удаления и проверенную процедуру запроса удаления.
- Возрастной gate 18+, стабильную обработку 429/лимитов/ошибок и понятный отказ без финансового изменения.
- Отдельное заключение российского юриста и подтверждение владельцем продукта.

До выполнения всех пунктов ИИ доступен только на синтетических данных в тестовой среде; для реальных данных пользователей из России он выключен.
