# Finance Mobile v1 — утверждённая спецификация

## Цель и границы

Самостоятельный Android-клиент для существующего finance-bot: Kotlin, Jetpack Compose, Material 3, FastAPI и существующие Python services/ai/database. REST API пригоден для будущего iOS-клиента. Telegram остаётся работоспособным. Работа ведётся в `feat/android-fastapi`; main не изменяется.

В проверенных локальных папках и удалённых ветках предыдущая мобильная реализация не обнаружена. База разработки: commit cfaa013e1c977db24d7ab81944d0113ca79daea9. Этот документ фиксирует требования из утверждённой переписки «Уточнения перед разработкой».

## Архитектура и данные

- Android: Compose UI → ViewModel → Repository → HTTPS REST; локальный кэш последних данных, сохранение настроек, защищённое хранение сессии Android Keystore.
- Backend: FastAPI `/api/v1`, username/password, Argon2id, короткоживущий JWT access token, отзываемые одноразовые refresh tokens.
- Identity: независимый внутренний UUID, без Telegram ID. Auth хранится отдельно. Каждый аккаунт получает собственную SQLite-базу с существующей схемой core. Это изолирует глобальные legacy debts/settings без разрушительной миграции рабочей Telegram-базы. Внутри базы аккаунта core использует технический user_id=1.
- Выбор базы осуществляется ContextVar на время авторизованного запроса. Вне этого контекста действует прежний DB_PATH. Нельзя менять глобальный DB_PATH на каждом запросе.
- Существующие алгоритмы OCR/Vision, анализа корзины, классификации, бюджетов, прогнозов, recurring, сравнения цен, shopping и банковского PDF переиспользуются.
- OCR и AI работают на backend. Недоступность Ollama/Tesseract отображается явно; ручной ввод остаётся доступным.
- Запись распознанных данных требует предварительного просмотра и подтверждения. Импорт повторного PDF не создаёт повторные операции. Все запросы ограничены текущим аккаунтом.

## Функции и экраны

| Раздел | Обязательное поведение |
| --- | --- |
| Вход | Регистрация, подтверждение пароля, вход, refresh, выход, сохранение сессии |
| Онбординг | Имя, месячный бюджет, завершение настройки |
| Главная | Расходы/доходы месяца, остаток бюджета, дневной лимит, последние операции |
| Операции | Ручной расход/доход; свободный текст с preview; фильтры; исправление, удаление с восстановлением долга, повтор |
| Чеки | Фото/галерея; OCR + Vision; магазин, дата, итог, позиции, расхождения; исправление и подтверждение; анализ корзины и источник оценки |
| Аналитика | Неделя/месяц/90 дней/год; категории, динамика, баланс, прогноз конца месяца |
| Бюджеты | Общий и категорийные лимиты; недельный продуктовый лимит; предложение бюджета с подтверждением |
| Долги | Добавление/изменение, остаток, ставка, платёж, прогноз погашения |
| Recurring | Выявление повторов по истории, ближайшие платежи, скрытие ошибочных серий |
| Цены | Поиск товаров, история и сравнение цен по своим чекам |
| Покупки | Предложения по ритму покупок, отметка купленного |
| Bank PDF | Выбор PDF, preview, сверка итогов, исключение дубликатов, подтверждение |
| Профиль | RU/EN, system/light/dark, адрес backend, статус AI/OCR, demo seed, выход |

Дизайн: крупные суммы, светлые/тёмные карточки, lime-акцент, нижняя навигация «Главная / Аналитика / Добавить / Долги / Профиль». Пустые, загрузочные и ошибочные состояния. Локализация элементов UI через Android resources; названия исходных данных сохраняются. Package `com.decorix.finance`, minSdk 26. Для эмулятора backend доступен по `http://10.0.2.2:8000`; HTTP допускается только debug-сборкой.

## API

`auth/register`, `auth/login`, `auth/refresh`, `auth/logout`, `users/me`, `dashboard`, `transactions`, `transactions/parse`, `transactions/{id}`, `transactions/{id}/repeat`, `receipts/analyze`, `receipts/confirm`, `budgets`, `budgets/suggest`, `debts`, `debts/{id}/payment`, `reports/summary`, `recurring`, `products`, `shopping-list`, `import/bank-statement`, `import/confirm`, `settings`, `demo`, `health`.

Pydantic проверяет конечные положительные суммы, тип операции, категории, даты и размеры данных. Токены не попадают в логи. Загрузки ограничены размером, временные файлы удаляются. Ошибки API имеют машинные коды.

2. Проверить регистрацию/login/refresh/logout, истечение и отзыв токенов, изоляцию двух пользователей при параллельных запросах.

4. Собрать debug APK, установить в Android-эмулятор, проверить вход, операцию, RU/EN, темы, перезапуск и сетевую ошибку.
5. Поставить исходники, README_ANDROID.md, APK и честный отчёт о проверках и ограничениях.

Не входят: банковские API, SMS/push parsing, платежи, инвестиции, мультивалютные счета, SaaS, Firebase, iOS UI, offline-очередь изменений.
